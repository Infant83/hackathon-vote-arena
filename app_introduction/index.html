Project Introduction

Vibe Vote Arena

사내 해커톤 본선에서 관객 투표, 응원 메시지, 퀴즈, 행운권 추첨을 한 흐름으로 운영하기 위한 실시간 행사 플랫폼입니다. 이 문서는 앱의 핵심 스펙부터 Cloudflare 호스팅, 보안 경계, 실시간 아키텍처, 운영 명세까지 단계별로 설명합니다.

Step 01

제품 한눈에 보기

이 앱은 단순 투표지가 아니라 행사장의 관객, 사회자, 운영자를 연결하는 실시간 참여 레이어입니다. 관객은 모바일에서 별과 응원 메시지를 보내고, 운영자는 관리자 콘솔에서 점수, 메시지, 추첨, 퀴즈, 송출 화면을 통제합니다.

Audience + Admin + Wall
10 stars

별 예산 배분

참가자는 관리자가 정한 총 별 개수를 여러 팀에 나눠 보냅니다. 기본값은 총 10개, 팀당 최대 5개입니다.

SSE live

실시간 동기화

관리자, 송출 화면, 관객 화면은 역할별 상태를 SSE로 받고, 연결 문제가 있을 때만 fallback 조회를 사용합니다.

DO state

Cloudflare 저장

운영 배포에서는 Durable Object가 행사 방 상태를 잡고, 정적 화면은 Workers Static Assets로 서빙합니다.

XLSX export

결과 보존

관리자는 행사 결과를 XLSX로 내보내고, 인증 상태에서 원본 JSON 백업도 받을 수 있습니다.

Step 02

화면과 사용자 흐름

하나의 React 앱이 URL 경로를 기준으로 관객용 투표 화면, 관리자 콘솔, 발표장 송출 보드, 팀별 직접 편집 화면으로 분기합니다.

Route based shell

핵심 화면

경로 대상 주요 역할
/vote 관객 등록, 별 배분, 응원 메시지, 퀴즈 답변, 내 당첨 이력 확인
/admin 운영자 실시간 현황, 운영 설정, 메시지 관리, 참여자 관리, 추첨, 퀴즈, 결과 내보내기
/admin?showCheer=1 사회자/발표장 응원 버블 Showup, 섞기, 드래그, 클릭 후 메시지 공개
/wall 발표장 송출 실시간 별 현황, 응원 메시지, 행운권 추첨, 퀴즈 진행 화면
/team/:id?key=... 팀 담당자 팀별 정보 직접 편집 링크, editKey 기반 접근

관객 참여 흐름

  1. 1
    이름, ID, 소속 등록

    브라우저 device id와 함께 참여자를 만들거나 기존 참여 내역을 복원합니다.

  2. 2
    팀별 별 배분

    마감 전에는 별을 회수하거나 다시 배분할 수 있고, 팀별 총점과 순위는 관객에게 숨깁니다.

  3. 3
    응원 메시지 작성

    별을 준 팀에만 메시지를 보낼 수 있으며, 메시지는 Enter로 전송됩니다.

  4. 4
    추첨 자동 응모

    별 1개 이상과 공개 응원 메시지를 만족하면 행운권 후보가 됩니다.

Step 03

주요 기능 명세

현재 MVP는 투표, 응원, 퀴즈, 추첨, 콘텐츠 관리, 결과 내보내기를 한 화면 운영 콘솔에서 조합할 수 있게 구현되어 있습니다.

Functional spec
영역 명세 운영 포인트
참가자 등록 이름, ID, 소속을 받고 익명 브라우저 device id를 함께 사용합니다. 같은 이름과 ID로 다시 접속하면 기존 내역을 이어받습니다. 강한 본인 인증 대신 최소 개인정보와 운영자 사후 확인을 택한 설계입니다.
별 투표 총 별 예산, 팀당 최대 별 수, 마감/재개, 타이머를 관리자가 설정합니다. 기본값은 총 10개, 팀당 최대 5개입니다. 관객 화면은 순위와 팀별 총점을 숨기고, 관리자와 송출 화면만 현황을 봅니다.
응원 메시지 별을 준 팀에만 작성 가능하며, 숨김 처리된 메시지는 일반 패널과 Showup에서 제외됩니다. 최근 메시지는 상태 payload에 포함하고, 과거 메시지는 /api/cheers로 페이지 조회합니다.
Showup 버블 별 수가 큰 참여자 버블을 크게 표시하고, 클릭 전에는 작성자와 메시지를 숨깁니다. 클릭 후 큰 카드로 내용을 읽습니다. 사회자는 버블을 섞거나 드래그할 수 있습니다.
행운권 추첨 공개 응원 메시지, 현재 1위 팀, 상위권/중위권/하위권 조건, 여러 팀 참여, 가장 긴 메시지, 메시지 3개/5개 이상 등 룰을 지원합니다. 이미 당첨된 참여자는 다음 추첨 후보에서 제외하고, 응원 메시지 가중치를 완만하게 적용할 수 있습니다.
퀴즈 퀴즈 준비, 카운트다운, 오픈, 정답 확인, 마감 상태를 공유합니다. 기본 제출 기회는 3회, 초기 확인 딜레이는 20초입니다. 사회자가 정답 확인 모드 전환으로 초기 딜레이를 건너뛸 수 있습니다.
운영 콘텐츠 팀 정보, 로고/사진, 화면 문구, 추첨 상품, 퀴즈 문제와 인정 답안을 관리자 화면에서 편집합니다. Cloudflare 운영에서는 Durable Object storage에 저장되며, 로컬 Node는 teams.json과 public/team-logos를 갱신합니다.
결과 내보내기 XLSX 내보내기와 관리자 인증 기반 /api/export 원본 JSON 백업을 제공합니다. 행사 종료 직후 XLSX와 JSON을 모두 내려받는 절차가 필요합니다.
Step 04

프로그램 아키텍처

프론트엔드는 React 단일 앱이고, 서버는 로컬 Node harness와 Cloudflare Worker가 같은 REST/SSE 표면을 맞추는 이중 런타임 구조입니다. 이 덕분에 로컬 리허설과 운영 배포의 프론트엔드 코드를 거의 동일하게 유지합니다.

React + REST + SSE
Client Browser surfaces /vote, /admin, /wall, Showup, 팀 편집 화면
→
API REST + SSE boundary /api/*는 상태 변경과 조회, /events는 역할별 SSE 스트림
→
State Node memory or Durable Object 로컬은 프로세스 메모리, 운영은 ArenaRoom Durable Object storage

프론트엔드

src/App.tsx가 라우트, 상태 연결, 화면 컴포넌트, 결과 XLSX 생성, 팀/퀴즈 편집 UI를 담당합니다.

로컬 서버

server.mjs는 빌드된 dist 정적 파일과 /api/*, /events를 함께 서빙합니다.

운영 서버

worker/index.ts는 관리자 인증과 라우팅을 처리하고, 상태 처리는 Durable Object ArenaRoom에 위임합니다.

Step 05

호스팅과 서빙 방식

실제 상태 공유 검증은 Vite dev server가 아니라 Node realtime 서버나 Cloudflare Worker에서 해야 합니다. Vite-only 모드는 UI 작업에는 빠르지만 여러 기기의 공유 상태 검증에는 충분하지 않습니다.

Local vs Cloudflare

로컬 리허설

npm install
$env:ADMIN_PASSCODE="운영팀이_정한_passcode"
npm run realtime

npm run realtime은 npm run build 후 node server.mjs를 실행합니다. 기본 포트는 5173이고, 같은 네트워크의 모바일은 PC IP로 /vote에 접속합니다.

Cloudflare 운영 배포

npx wrangler secret put ADMIN_PASSCODE
npm run cf:deploy:dry-run
npm run cf:deploy

wrangler.jsonc는 Worker 이름 hack, 정적 assets 디렉터리 ./dist, Durable Object ArenaRoom, run_worker_first의 /api/*와 /events*를 정의합니다.

운영 주소 정합성 주의

현재 문서에는 README.md의 hack.infant83.workers.dev와 TODO.md, 운영 이슈 리포트의 hack.lgdisplay.workers.dev 흔적이 함께 남아 있습니다. 최종 소개 자료나 행사 안내문에 넣을 주소는 Cloudflare Dashboard 기준으로 하나만 확정하는 것이 좋습니다.

Step 06

실시간 상태 흐름

모든 관객에게 모든 내부 상태를 보내지 않습니다. 역할별로 상태를 가공하고, 이미지 같은 큰 미디어는 반복 전송에서 제외하는 media=slim 흐름을 사용합니다.

Role-shaped state

상태 전송 전략

  • /events?role=admin과 /events?role=wall은 관리자 인증이 필요합니다.
  • /events?role=vote&media=slim은 관객에게 필요한 상태만 보냅니다.
  • 관객 role에서는 전체 참여자 목록 대신 자신의 참여자 상태와 본인 관련 수상 이력만 받습니다.
  • 숨김 메시지는 일반 관객에게 보이지 않고, 본인이 작성한 숨김 메시지는 응모 상태 안내를 위해 남습니다.

부하 완화 전략

  • SSE가 살아 있으면 관객 화면은 반복 polling을 하지 않습니다.
  • SSE 오류가 난 브라우저만 fallback polling으로 복구합니다.
  • 큰 inline 이미지는 slim state에서 빼고 브라우저가 직전 full state 이미지를 보존합니다.
  • 퀴즈 답변 제출은 제출자 POST 응답으로 즉시 피드백하고, 모든 관객에게 매 답변마다 full broadcast하지 않습니다.
Step 07

보안과 개인정보 경계

이 앱은 사내 행사 MVP에 맞춰 관리자 보호와 최소 개인정보 수집을 우선했습니다. 강한 신원 인증, 고급 rate limit, 감사 로그는 향후 개선 후보로 남아 있습니다.

Security boundary
항목 현재 구현 주의/개선 후보
관리자 인증 ADMIN_PASSCODE 기반 로그인. 쿠키 vibe-vote-admin은 passcode의 SHA-256 토큰이며 HttpOnly, SameSite=Lax, 운영 HTTPS에서는 Secure가 붙습니다. passcode는 레포에 넣지 않고 Cloudflare secret으로 관리합니다. 회전 절차는 행사 전 확정이 필요합니다.
관리자 API 보호 메시지 관리, 퀴즈 운영, 투표 마감, 참여자 관리, 설정, 팀 설정, 추첨, reset, export, admin/wall SSE가 인증 필요 경로입니다. 팀 직접 편집 경로는 별도 editKey 설계이므로 배포 전 키 유출을 확인합니다.
참가자 식별 이름과 ID를 정규화하고, 익명 브라우저 device id를 쿠키와 localStorage에 저장해 같은 참여자를 복원합니다. 사번, 이메일, 사진, 카메라 QR, 강한 device fingerprint는 기본 흐름에 넣지 않습니다.
데이터 노출 제한 관객 role 상태에서는 전체 참여자 목록과 별 이벤트 feed를 제거하고, 팀별 총점/순위를 관객 UI에 노출하지 않습니다. 운영자가 다운로드한 JSON/XLSX는 별도 보관 정책이 필요합니다.
남은 보안 과제 기본 input sanitize와 권한 경계는 있으나, 세밀한 rate limit과 관리자 audit log는 아직 TODO입니다. 대규모 행사 이후에는 D1/R2 또는 외부 저장소, append-only archive, rate limit, 운영자 감사 로그를 추가하는 것이 좋습니다.
Step 08

데이터 모델과 저장

상태 모델은 행사 진행에 필요한 모든 값을 하나의 이벤트 상태로 묶고, 화면별로 필요한 부분만 잘라서 내려보냅니다. 운영 배포의 Durable Object snapshot은 행사 상태 저장소이지 장기 아카이브를 대체하지 않습니다.

EventState

핵심 상태 객체

  • Team: 팀 ID, 코드, 이름, 프로젝트명, 멤버, 색상, 로고/사진 프레임, 총 별, 순위, 환산점수
  • Participant: 참여자 ID, device ids, 이름, ID, 소속, 별 배분, 응원/당첨 상태
  • CheerMessage: 메시지 ID, 팀 ID, 작성자, 내용, 작성시각, 숨김 여부
  • VoteEvent: 별 이동 이벤트, 이전/이후 별 수, 증감값, 시각
  • QuizState: 퀴즈 라운드, 모드, 문제, 답변, 정답자, 타이머 경계
  • AwardRecord: 행운권/퀴즈 수상 이력, 상품, 룰, 생성시각

저장 위치

  • 로컬 Node: 참여자, 별, 응원, 퀴즈, 추첨 상태는 프로세스 메모리입니다.
  • 로컬 Node: 운영 콘텐츠 저장은 teams.json과 public/team-logos에 반영됩니다.
  • Cloudflare: 상태 snapshot은 Durable Object storage의 event-state-v1에 저장됩니다.
  • Cloudflare: 큰 inline media는 event-media-v1:* 키로 분리 저장하고 snapshot에는 token만 둡니다.
  • 응원 메시지는 내부 최대 5000개, 퀴즈 답변은 최대 1000개 보존 기준이 있습니다.
Step 09

API 표면

Node 서버와 Cloudflare Worker는 같은 API 표면을 맞춥니다. 프론트엔드는 런타임이 로컬인지 Cloudflare인지보다 /api/*와 /events의 계약을 기준으로 동작합니다.

REST contract
API 권한 용도
GET /api/state?role=... vote 공개, admin/wall 인증 현재 상태 조회. media=slim으로 반복 payload를 줄일 수 있습니다.
GET /events?role=... vote 공개, admin/wall 인증 SSE 실시간 상태 스트림입니다.
POST /api/register, /api/vote, /api/cheer 관객 참가자 등록, 별 배분, 응원 메시지 제출입니다.
POST /api/admin/login, /logout, GET /api/admin/status 관리자 passcode 로그인, 로그아웃, 세션 확인입니다.
POST /api/settings, /api/close, /api/reset 관리자 별 예산, 타이머, 테마, 퀴즈 제한, 마감/재개, 전체 reset 제어입니다.
POST /api/cheer/moderate, /api/cheer/bulk 관리자 응원 메시지 숨김/공개/삭제 처리입니다.
POST /api/raffle, /api/raffle/stage, /api/raffle/reset 관리자 추첨 실행, 송출 stage 제어, 추첨 이력 초기화입니다.
POST /api/quiz/*, POST /api/quiz/answer 운영 제어는 관리자, 답변 제출은 관객 퀴즈 출제/준비/확인/마감/이력 reset과 관객 답변 제출입니다.
POST /api/team-config, GET /api/team-config/apply 관리자 운영 콘텐츠 저장. POST 차단 사내망을 위한 압축 GET fallback도 있습니다.
GET /api/cheers, GET /api/export cheers vote 조회 일부 공개, export 관리자 과거 응원 메시지 페이지 조회와 원본 JSON 백업입니다.
Step 10

운영과 검증

행사 플랫폼은 코드가 빌드되는 것만으로 충분하지 않습니다. 리허설에서 실제 기기, 실제 네트워크, 관리자 인증, 송출 화면, Reset과 export까지 함께 확인해야 합니다.

Runbook

개발 검증 명령

npm run lint
npm run build
npm run cf:deploy:dry-run

UI나 서버 동작을 바꾸면 lint/build를 먼저 통과시키고, Cloudflare 배포 전에는 dry-run으로 Worker 번들을 확인합니다.

행사 전 리허설 체크

  • 관리자 passcode 설정과 로그인 확인
  • /vote 등록, 별 배분, 회수, 응원 메시지 전송
  • /admin 메시지 숨김/공개, 설정 변경, Reset, 테스트 데이터 주입
  • /wall 실시간 현황, 퀴즈, 행운권 송출
  • /admin?showCheer=1 버블 클릭 전/후 정보 노출 확인
  • 모바일 390px 전후에서 텍스트와 별 버튼 겹침 확인
  • 행사 종료 후 XLSX와 /api/export JSON 백업

현재 남은 P0

최종 팀 정보, 퀴즈 문제/상품, 행운권 상품, 사내망/모바일망 접속, 당일 역할 분담, 긴급 복구 1페이지가 행사 전 확정 항목입니다.

향후 안정화

append-only archive, fallback polling jitter, 짧은 state 캐시, structured observability, rate limit이 다음 안정화 후보입니다.

리팩토링 후보

src/App.tsx 역할별 분리, server.mjs와 worker/index.ts 공통 로직 공유 모듈화, team config schema 명시화가 권장됩니다.
